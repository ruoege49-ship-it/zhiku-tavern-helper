# 智库 · SillyTavern 扩展

作者 **if love** · 版本 **0.8.13**。NovelAI 生图、画师库、例图、角色、衣柜、标记生图与共享上传。

## 安装与更新

1. 打开酒馆「扩展」→「安装扩展」。
2. 粘贴仓库地址：`https://github.com/ruoege49-ship-it/zhiku-tavern-helper`
3. 安装后刷新酒馆，通过扩展设置「打开智库」、魔棒菜单「智库」或侧边票根打开。
4. 后续在扩展管理里点击更新，再刷新页面。

扩展版不需要酒馆助手。最低宿主版本为 SillyTavern 1.14.0；新版本宿主支持启停钩子，旧版本启停后刷新页面。

**从脚本版切换：先停用酒馆助手脚本库中的旧「智库」，再启用扩展版。** 同一个酒馆用户下，原有画师库文件、图片、NovelAI 设置与共享身份继续沿用，无需重新导入画师库。

## 共享

共享页右上角「＋ 上传」可填写名称、署名、画师串、标签和说明，并附上最多 6 张例图。发布后自动打开「我分享的」。内置共享服务器地址，无需邀请码。已有自定义服务器地址优先使用。NovelAI Key 由使用者自己在酒馆内配置。

## 文生图标记与不发送正则

回复中使用完整标记：

```text
image###1boy, solo, sunset, cinematic lighting###
```

自动使用标记里的提示词调用 NovelAI，结合当前画师串、质量设置及参考图配置；不另外请求聊天 AI 改写剧情。生成结果单独保存在消息扩展数据中，按标记位置显示；原消息与提示词保留，同楼多个标记按顺序生成。普通回复不会自动生图。标记默认显示为收起的「图片提示词」，旁边有「生成图片」按钮，可单独生成该标记；生成中禁用按钮，失败后可点击「重试生成」。魔棒菜单使用 与酒馆一致的单色图片图标。

「开启标记自动生图」默认开启，位于智库设置顶部，也可直接在酒馆的智库扩展设置中切换；关闭选择会保存。开始与结束标记在「文生图标记」中调整。若安装过智绘姬，默认读取它的 `startTag` / `endTag`；否则使用 `image###` / `###`。流式回复在消息完成后识别，不处理尚未闭合的标记。重复消息渲染不会重复生成；切换聊天或改写消息后，不把在途图片插到其他楼层。

内置并自动注册 **「智库 · 生图标记不发送」** 正则：仅过滤发给聊天模型的用户／角色消息文本，保留聊天原文供生图识别。另有「智库 · 生图标记折叠」显示正则，负责折叠块；两条规则都保留编辑原文。修改开始、结束标记时正则同步更新。原有其他正则保留。此功能使用酒馆自带的 Regex 扩展，请保持它启用。

旧的「每楼自动生成」已移除。没有标记的旧楼不会因升级或重新打开聊天而自动扣点。失败时保留标记，可以通过楼层图片按钮重试。

- 画面方案随消息保存，可在图片提示词折叠块查看标题、瞬间、原句和分级；修改单张图后显示新的提示词。同一句对应多张图时保留模型返回的顺序，保存失败会回退正文与方案。

完整默认提示词见 `src/illustration-plans.js` 的 `DEFAULT_ILLUSTRATION_PROMPT`。只客观标记成人内容，画面标签描述非露骨的可见信息。自定义输出仍需保留格式契约；「写完再请求」也兼容旧的 `images: [{after, tags}]` 格式，但须提供正文中真实存在的定位句。旧生图世界书已输出标记的楼层不会再次请求生成画面方案。

## 0.8.12 改动

- 「跟正文一起写」「写完再请求」都要求模型逐图写入角色标记；每张图选一个决定性瞬间。图片张数继续使用玩家现有选择，外部预设里的张数规则保持原样。
- 「写完再请求」只使用完整的 `<content>...</content>` 正文；没有该标签时读取普通正文并去除思考、折叠区。插图放在正文内，避免落入末尾状态栏。修正等长回复被误判为已处理的问题。
- 角色页预览改称「候选角色外貌」，明确它展示的是可用资料，不是每张图实际发送名单。纯英文图片标签继续直接生图；已有图片保留，手动重新生成时采用新规则。

### 逐图角色标记

先在角色页登记外貌和名字／别名，并在「这次聊天」启用。例如本图只画小红和小蓝：

```text
image###2girls, garden, $小红-sfw-upperbody$, smiling, $小蓝-sfw-upperbody$, waving###
```

JSON 写法也能识别角色：

```text
image###1girl, garden, ${"name":"小红","angle":"from front","upperBody":"sfw","lowerBody":"hidden"}$, smiling###
```

此适配读取智库里保存的外貌、固定衣服和参考图；`angle` 进入该角色的提示词。智库现有角色数据没有智绘姬的上下半身独立字段，身体状态后缀用于识别协议，不会按部位重建外貌或衣服。需要不同衣着时，在智库衣柜或该图标签里设置。

没有角色的空镜直接写 `image###no humans, lake, sunset###`。普通英文标签无需加角色标记；`$小红$` 裸名字不属于有效格式。

使用自定义世界书／外部生图预设时，在原有规则中补上这一段即可，张数继续由原有玩家设置控制：

```text
每张图片只描绘一个瞬间。对该图实际入画、已在智库登记并启用的角色，在 image###...### 内逐人写 $角色名字-sfw-upperbody$，随后写该角色当下的英文动作、表情等标签。未入画的人不写标记，空镜不写角色标记。角色名字可用中文，其余画面标签用英文。没有登记的角色直接写英文外貌标签。图片数量沿用玩家设置。
```

- 历史生图（参考智绘姬的图片缓存）：生图页最下面的「历史生图」记下生图页和聊天标记生成的图，最多 300 张，刷新后也在。
  - 每张另存一张小缩略图，画廊只加载缩略图，手机上也快。
  - 点开能看到提示词、种子、尺寸、模型，可以「用这组参数再生成」（填回生图页）、下载、删除。
  - 多选下载、多选删除，一键清理 7 天 / 30 天前的。删除会真的删掉图片文件，聊天里用到的地方也会显示不出来。
- 聊天标记重新生成不再覆盖旧图：每个标记最多留 10 个版本，展开图片后用「‹ 上一版 / 下一版 ›」切换；「删除当前图片」只删正在看的这一版。
- 修复手机上「更多参数」里步数、噪声表被挤成一条。

- 修复已经生成过的图又被请求一次：别的脚本改了标记前面的文字（位置挪了），或者酒馆把楼层换成了新对象时，智库认不出已经生成过。图多的时候还会因为请求太多而失败。
- 正文自动插图（设置 → 文生图标记 → 正文自动插图），不用再另挂生图世界书：
  - 「跟正文一起写」：每次发消息时告诉聊天 AI 在有画面感的地方顺手写一行生图标记。不多花请求，但要模型听话。
  - 「写完再请求」：回复写完后，用「AI」设置里选的 API 另外请求一次，挑画面写标签并插回正文（和智绘姬的「自动 LLM 请求生图」一样）。

- 角色按名字触发（历史行为，已由 0.8.12 的逐图角色标记替代）：曾按整楼提及匹配外貌和参考图。

- 在扩展管理里停用或删除智库时，自动删掉智库加的两条全局正则（「智库 · 生图标记不发送」「智库 · 生图标记折叠」），聊天里的生图标记恢复原来的显示（比如交回给智绘姬）。刷新页面不会删。

## 0.8.8 改动

- 画师串原样保存：存进画师库或「整串改写」时，`{}` `[]`、`1.2::a, b::` 这类写法、顺序和小数位都按你写的原样保存和发送，不再拆开改写成 `1.1::artist:x::`；手动改回的权重也不会再被改回去。用 ± 按钮调权重、加删画师后才会按新内容重新拼。以前已经被改写的画师组，用「整串改写」贴一次原来的串就恢复了。
- 衣柜新增「从穿搭管理器导入」（[Outfit-Manager](https://github.com/wenshui012/Outfit-Manager)）：可以直接读同一个酒馆里装着的穿搭管理器（后端 / 浏览器存储都认），也可以选它导出的 .json（完整备份、只 User、单个角色、全部角色都行）。每组可以选给哪个角色或只存进衣柜，同名角色自动对上。文字描述用 AI 转成标签，配饰自动分到配饰栏，套装里的单品一起带上；只有图的可以用 AI 看图。只读不写，重复导入会跳过已经导过的。
- 氛围编码失败（NovelAI 返回 500 等）时不再让整张图失败：这张先不带氛围出图，并提示是哪张氛围图没编上。编码前统一转成 PNG，遇到 5xx 自动再试一次。
- 设置里点「测试」时，如果这台设备连不上查余额的 api.novelai.net（Failed to fetch），改成提示「查不到余额，去生图页试一张」，不再显示成连不上。
- 负面预设加「自定义」：自己写一段固定负面，每次出图都加在负面最前面（生图页、聊天标记出图、例图、试穿都带上）。第一次选会先放进原来预设的内容，在它基础上改。
- 修复手机上配合部分美化时，智库窗口只显示上面一截、背景透明、透出后面聊天的问题。窗口和弹窗改挂到页面最外层，层级抬到最高，背景不再跟着美化的颜色变量变透明。

## 开发与验证

入口为 `index.js`，完整本地运行代码为 `runtime.js`，扩展清单为 `manifest.json`。

运行 `node tools/build-extension.mjs` 可从完整脚本 JSON 和 `src/index.js` 重建扩展。扩展不从远程拉取代码执行。

标记识别及过滤源文件：`src/marker-generation.js`；接入脚本：`tools/apply-markers.mjs`。模拟宿主测试已覆盖消息事件 → NovelAI 请求正文 → 图片上传 → 原位插入和保存、重复事件、普通回复、切换聊天及不发送正则。真实付费出图接口未在本轮调用。

清单、语法、模拟宿主中的启动、原生入口、共享署名表单、停用清理及再启用检查通过。接口核对依据为本机 SillyTavern 1.14.0，提交 `fbf789fa7480fafe0275b2f79e4384e77ae689a7`；扩展规范见 [官方文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)。浏览器内实际安装点击验收尚未执行。

## 绑定与切换

- 角色卡绑定画师串：进入该角色的聊天自动切换；离开到没绑定的角色时，换回绑定前在用的画师串。
- 「只用一次」「每生成一张就换一个」在聊天里每出一张标记图后生效。
- 角色参考只在「角色」页给每个角色单独绑（建组、加图、调「像不像」都在那里）；标记生图时按出场角色带上，没绑就不用。氛围页只管氛围。

## 生图队列

手动点击仅生成对应标记；多个标记时楼层入口提示选择具体按钮。每张独立显示排队、生成、保存状态。智库内普通生图、局部重绘和氛围编码共用串行队列，请求间隔至少 1.5 秒；429 按 Retry-After 或 5/10 秒退避，最多重试两次。用酒馆里的 NovelAI key 时，酒馆会把 429 报成 500，这种情况同样等待后重试。当前队列仅协调本页面智库，不包含智绘姬的跨设备云端队列。
